## AyuVahak decisions informed by these facts

- Preserve FHIR R4 4.0.1 as the first interoperability baseline because it is the frozen Volume I decision and aligns with the verified current IPS, mCSD, and SMART publications. This is a project decision, not a requirement imposed by those standards.
- Keep R4B and R5 behind explicit adapter/version boundaries. Add support only for a named partner/profile need, with version-specific conformance tests and explicit loss reporting. Never promise automatic or lossless conversion.
- Use mCSD first for Directory-owned discovery projection. ITI-90 query is the initial discovery contract; update/feed options are separately enabled only when a deployment’s source and reconciliation agreement justify them.
- Use IPS only as an optional, purpose-limited source representation for a Referral-owned patient-context retrieval. Do not persist the full document or create a patient record.
- Treat SMART as one possible external authorization protocol, especially for FHIR partners. External token scopes constrain partner access but do not replace local AyuVahak authorization.
- Do not mandate NEMSIS, IHE transport profiles, or any provider-specific dispatch API. Phase 10 must work in local/manual mode and can add a deployment-specific adapter only after a real partner contract exists.
- Keep standard fact, external source evidence, and AyuVahak-owned coordination state distinct. Profile validity is not proof of truth, freshness, authority, or permission.
