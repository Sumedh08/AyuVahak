# Phase 8 mCSD Profile Package Preflight

**Checked:** 2026-10-15
**Purpose:** establish whether the frozen mCSD profile set can be loaded for local HAPI validation. This is standards/tooling research only; no healthcare endpoint was contacted.

## Package identity and status

IHE publishes the mCSD Implementation Guide as the FHIR conformance package **`ihe.iti.mcsd#4.0.0`**, based on **FHIR R4 4.0.1**. The IHE publication identifies 4.0.0 as a Trial-Implementation publication and links the package from its download/dependency page. The public package catalog lists 22 profiles and the same package id/version. This is a **FHIR NPM-format package**, distributed through a FHIR package registry; it is not a Java/Maven library or an ordinary application package from npmjs. [IHE mCSD download and dependency page](https://profiles.ihe.net/ITI/mCSD/download.html), [IHE mCSD package listing](https://simplifier.net/packages/ihe.iti.mcsd/4.0.0), [Firely instructions for FHIR packages using npm](https://docs.fire.ly/projects/Firely-Terminal/package_management/Using-NPM-instead.html)

The IHE source repository identifies its guide material under **CC BY 4.0**. The published guide separately calls out DICOM terminology excerpts with NEMA copyright. AyuVahak therefore does not redistribute the full archive; only reviewed StructureDefinitions are included, with source attribution and license details recorded in [`PROFILE_ARTIFACTS_NOTICES.md`](../../src/main/resources/org/ayuvahak/platform/fhir/profiles/PROFILE_ARTIFACTS_NOTICES.md). [IHE mCSD source repository and license](https://github.com/IHE/ITI.mCSD), [IHE mCSD download page IP statements](https://profiles.ihe.net/ITI/mCSD/download.html)

The package depends on R4 packages including `hl7.terminology.r4#6.3.0`, `hl7.fhir.uv.extensions.r4#5.2.0`, and `ihe.iti.balp#1.1.3`. Those exact versions matter to reproducible validation; the guide's QA report also lists older optional dependency versions, which should not be selected accidentally. [IHE mCSD dependency table](https://profiles.ihe.net/ITI/mCSD/download.html), [IHE mCSD QA report](https://profiles.ihe.net/ITI/mCSD/qa.min.html)

## Local implementation outcome

HAPI documents `NpmPackageValidationSupport` as a validation-support module for FHIR NPM conformance packages and exposes `loadPackageFromClasspath(...)`. The implemented parser loads the curated profile package from local classpath resources and verifies the expected canonical/version is available at startup. It does not configure remote package, terminology, or reference resolution. When a requested profile is absent or unsupported, validation fails explicitly rather than falling back to core R4 validation and calling that mCSD conformance. [HAPI Instance Validator: packages](https://hapifhir.io/hapi-fhir/docs/validation/instance_validator.html), [HAPI validation-support modules](https://hapifhir.io/hapi-fhir/docs/validation/validation_support_modules.html), [HAPI `NpmPackageValidationSupport` source](https://github.com/hapifhir/hapi-fhir/blob/master/hapi-fhir-validation/src/main/java/org/hl7/fhir/common/hapi/validation/support/NpmPackageValidationSupport.java)

The Phase 8 parser now loads a curated `ihe.iti.mcsd#4.0.0` package from the classpath and verifies the required profile canonical/version during startup. A local positive/negative test applies `IHE.mCSD.Organization|4.0.0`: a valid synthetic Organization passes, while one missing the profile's required type fails. No package registry, terminology service, or referenced resource is resolved at runtime; `Reference.reference` remains inert. Exact source/curated checksums, the selected seven StructureDefinitions, exclusions, and licensing notices are recorded in [`PROFILE_ARTIFACTS_NOTICES.md`](../../src/main/resources/org/ayuvahak/platform/fhir/profiles/PROFILE_ARTIFACTS_NOTICES.md).

## P8-02 implementation consequence and limits

The local P8-01 parser now provides a tested mCSD Organization profile seam in addition to R4 core support. This does not mean every mCSD resource/profile or every dependency in the full upstream package is supported. Only the seven listed StructureDefinitions are bundled; the other 17 upstream StructureDefinitions, all other indexed resources, and upstream terminology dependencies are excluded. Directory must select an available, exact source profile and fail closed when it is missing or unsupported. A profile result proves only the selected structural constraints; it does not confer trust or establish semantic equivalence. Full provenance and limitations are in [`PROFILE_ARTIFACTS_NOTICES.md`](../../src/main/resources/org/ayuvahak/platform/fhir/profiles/PROFILE_ARTIFACTS_NOTICES.md).
